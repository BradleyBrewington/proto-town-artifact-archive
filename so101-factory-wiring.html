01

Supervisor loop — one sortie at a time

factory.sh runs as the systemd user service factory (unit kept in systemd/): enabled at boot with linger on, restarted 30 s after any failure, and it exits only after a deliberate state/HALT. Each pass spawns one fresh execution agent (a "sortie") with no memory of the last one; the handoff file and git history are the only continuity.

Inside a sortie — what the agent actually does

The agent reads CLAUDE.md and state/handoff.json, then runs the collect loop with the tools in ./tools/. Every arm-touching step is a separate process; the dataset is only opened inside episode.py.

Coverage order is fixed, and the factory never finishes

70 start cells on a 4 cm grid, inside the staged reach quad and fully in the top camera's view (60 px margin). Serpentine sweep with a checkerboard interleave, so a half-finished pass still covers the whole workspace at half density. A cell marked --hard is deferred, never dropped: inside the quad, "unreachable" does not exist.

When every cell is covered or deferred, coverage.py next starts a new pass: all 70 cells go back to pending and hard cells get another try once per pass. It only prints DONE (→ verdict 0 → HALT) when state/STOP_WHEN_COVERED exists.

What "recorded" means

Frames enter the dataset only while the arm is moving inside Arm.recording(...) in lib/arm.py, and only episode.py opens that block. Resets, probes, recovery drags and technique trials are structurally unable to add frames: no REC badge, nothing to filter out later. Every motion primitive streams 30 Hz interpolated joint goals; each tick sends the goal, reads the servos, grabs both camera frames and appends one row. Thinking pauses (arm stationary) produce no frames, so legs stitch into one continuous episode whose action column is the goal the policy learns to emit.

File map — who may touch what

Permissions are enforced by .claude/settings.json on the agent's own tools (Read / Edit / Bash). The sortie runs headless in acceptEdits mode, so any Bash command not on the allow list is denied instead of prompted. Badges: write agent may Edit/Write directly · via tool written only by a script the agent may run · read · denied · system written by daemons or the supervisor.

05

Data in, data out

In — what an episode consumes

  • Camera frames from the daemon slots: top (fixed overhead, the pixel space every calibration uses) and wrist. Frames older than 0.5 s abort a tick as stale.
  • Servo positions, six joints, read every tick over the serial bus.
  • Calibration: touch-map homography, X target pixel, staged disc offset, reach quad, HOME pose, place bias, wrist-servo gain.
  • State: the coverage grid (which cell), sortie budget, handoff notes, lessons.
  • The agent's judgement: which technique, when to rehearse, when to defer.

Out — what the laptop pulls for training

  • dataset/so101_place_on_x/ — the demonstrations (64 MB at 9 episodes).
  • sidecars/ — labels; the reviewer quarantines label != success.
  • judge/ — evidence for spot-checking labels.
  • state/episodes_index.jsonl — the manifest.
rsync -av protopi5:~/so101_datagen/{dataset,sidecars,judge} ./factory/
rsync -av protopi5:~/so101_datagen/state/episodes_index.jsonl ./factory/

06

Labels, budgets, and the fences that hold them

The judge has no context on purpose

tools/judge.py crops 340 px around the saved X from a fresh daemon frame (the arm is HOME and clear), writes it to a temp directory, and runs a separate claude -p there with model claude-sonnet-5, Read as its only tool, and the fixed question in prompts/judge.txt. The temp cwd means no project CLAUDE.md, no memory, no history of the episode — it only sees the picture. Exit 0 = majority of the roll's footprint on the X, 3 = not, 4 = could not tell. The executor cannot override it. Every label so far has matched its photo on inspection.

Failed-but-completed placements are still committed, labelled fail: they are diagnostic and future DAgger seeds. Episodes with no demonstration (grasp never held, placement never ran) are discarded before the dataset sees them.

Doctrines baked into the tools. The reach quad is ground truth: any cell inside it is possible and "unreachable" is never a terminal state. Every place, drop or plow target passes lib/bounds.check_place_target so the roll never leaves the camera frame; if it does, recovery precedes all other work. Success is judged visually, at "majority on the X", not by centimetres. The arm's own encoder-FK space is used on both sides of every reachability test, so systematic model error cancels.
